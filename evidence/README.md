# Evidence Collection Guide

## Important source note

The supplied Linux Practical Test Package does **not** explicitly require screenshots, specify a screenshot count, or prescribe an evidence-submission format. This folder is an optional organization aid. Follow any additional instructions from your instructor.

Do not create screenshots in advance or submit sample/fabricated output. Save only evidence captured from your own Linux environment.

## Suggested screenshots

If your instructor asks for screenshots, capture them after completing the relevant step. Suggested filenames below are organizational suggestions, not requirements from the task sheet.

| Suggested filename | Capture after | What it can demonstrate |
|---|---|---|
| `01-activity1-directory-structure.png` | Activity 1 | `linux_lab`, `docs`, `scripts`, and file operations |
| `02-activity2-readme-and-commands.png` | Activity 2 | Your edited `readme.txt` and requested viewing/search commands |
| `03-activity3-permissions-ownership.png` | Activity 3 | `secure.txt` permission modes and owner shown by `ls -l` |
| `04-activity4-archive-restore.png` | Activity 4 | Archive, extraction, and restored files |
| `05-activity5-process-management.png` | Activity 5 | Background job, PID termination, and process check |
| `06-activity6-networking.png` | Activity 6 | Network commands and `testsite.local` check |
| `07-activity7-searching.png` | Activity 7 | Search results and `.txt` count |
| `08-activity8-package-management.png` | Activity 8 | APT update/install/version/remove and `packages.txt` |
| `09-activity9-hello-script.png` | Activity 9 | Script content, executable permission, and actual run |
| `10-activity10-system-monitoring.png` | Activity 10 | Disk, memory, log, uptime, users, and CPU commands |

A single screenshot may cover more than one command if the text is legible and the instructor accepts it.

## Terminal-output evidence

If text output is requested, paste your real output into files under `terminal-output/`. Identify the command and date/time where practical. Review outputs for private details before sharing.

## Evidence quality

- Show the command and relevant result together where practical.
- Keep text readable; avoid cropping out important context.
- Do not alter output to make a command appear successful.
- Redact secrets or unrelated personal information before public GitHub publication.
- Keep any required evidence files even if they match a pattern normally ignored by Git.
